# Diplodocus dogfooding assessment

Assessed on October 13, 2026, against Diplodocus commit
`dd35393d258f8192b66c66564fd0ff10f1e048e7`, the published revision pinned in the
Documentation workflow. The local checkout's two later commits add an example
vignette and support for R constants and deprecated topics; Datamonger does not
use those additions.

The site builds successfully and provides useful Python and R references.
Julia extraction cannot currently cover the complete maintained public surface.
The Rust CLI remains an authored guide because Diplodocus has no Rust API
extractor. The duplicate `diplodocus-api.toml` was removed so that local preview
and CI use one configuration.

## Limits exposed by this project

1. **Python overloads create duplicate entries.** `fetch_data` has a documented
   implementation page containing its overload signatures, plus three separate
   overload pages without prose. Search returns four indistinguishable Python
   results. Consolidating the overload declarations would make this API much
   easier to browse.
2. **Python titles expose implementation modules.** Public reexports resolve,
   but headings and search labels use names such as `datamonger._api.fetch_data`
   rather than `datamonger.fetch_data`. Prefer the public export path for display
   while retaining implementation locations for source links.
3. **Python fields need explanation.** The 49 dataclass fields have types but no
   individual prose in the source. `BUNDLED_REGISTRY` also lacks prose, and
   `DatasetData`, declared with `TypeAlias`, is classified as a constant. Improve
   source documentation for field semantics and check type-alias classification
   in Diplodocus.
4. **Eight R methods have no Rd alias.** These are `format.datamonger_int64`,
   `print.datamonger_int64`, `dim.datamonger_csr_matrix`,
   `print.datamonger_csr_matrix`, `print.datamonger_registry`,
   `print.datamonger_fetch_info`, `print.datamonger_data_info`, and
   `print.datamonger_cache_info`. They remain visible as undocumented API pages.
   Add maintained help topics or aliases in the R package.
5. **Automatic community discovery assumes resolvable site links.** The root
   `CONTRIBUTING.md` links to specification and operational documents outside the
   declared content. Automatic inclusion initially failed reference validation.
   A package-owned `community.md` now links to the repository guide instead.
   Diplodocus still parses the overridden source and emits 27 `LINE_PREFIX`
   warnings for list syntax; the published community page has no placeholders.
6. **Julia macro expansion is outside the static contract.** The concrete
   exceptions in `packages/julia/src/errors.jl` have no static definitions.
   Runtime-assisted extraction or maintained explicit definitions would be
   needed to include the complete API. Removing exports merely to obtain a
   successful build would conceal the actual coverage gap.

Four additional R diagnostics report file-level Rd attribution rather than
exact byte spans. These are tooling limitations, not missing package prose.

## Reproduce the Julia limit

Temporarily replace `targets = []` in the Julia package declaration of
`diplodocus.toml` with:

```toml
targets = [{ id = "api", extractor = "julia", path = "src/Datamonger.jl", role = "public-api" }]
```

Run `diplodocus check --config documentation/diplodocus.toml` from the repository
root. It reports 15 `julia-unresolved-definition` errors. Restore `targets = []`
afterward. Once extraction succeeds, add Julia members such as
`Datamonger.fetch_data` to the existing equivalent concepts.

## Validation

The refreshed configuration passes `check` and `build` in Datamonger's devenv
shell. Native R dependencies are available there, and the compiled extension
must exist before loading the checkout. CI installs those dependencies and
compiles the package before documentation extraction.

The generated site has 138 HTML pages. A local crawl found no missing local
links, assets, or heading anchors. Twelve representative pages passed desktop
and mobile checks at widths of 1440 and 390 pixels: successful HTTP responses,
one title, and no page overflow. Search returned Python and R `fetch_data`
results, and the browser reported no JavaScript errors. Screenshots of the R
overview and Python reference were inspected at both sizes.

Diplodocus's standard `site-capture` suite passed 63 tests with one skipped test.
That suite uses isolated Tiny Stats fixtures; it verifies the renderer but does
not substitute for the Datamonger checks above. The Wrangler deployment dry run
passed. No site was deployed.

At the time of this assessment, the R package contained no Rd examples or
R Markdown vignettes. The guide and README examples were display-only, so the
original site checks did not verify example execution.

## Offline execution follow-up

The [offline conformance walkthrough](../packages/r/vignettes/offline-conformance.Rmd)
now exercises the public `fetch_artifact()` and `fetch_data()` operations with
the shared mixed CSV fixture. Its inputs are bundled in the R package. Each run
seeds a private temporary cache, requires `offline = TRUE`, checks the five rows
and four typed columns against their expected values, and verifies the canonical
digest from the shared corpus. The article renders those values, reproducibility
metadata, and a PNG plot, then removes its cache.

A follow-up build with Diplodocus commit `03ade23` succeeded in the prepared
Datamonger environment, including the complete Julia target. The R article's
test also passed with network retrieval mocked to fail. These checks verify
execution of this offline example; the original published-site counts and
display-only guide examples above remain separate evidence.
